# Final Entertainment 방송 정산 시스템 — 개발백서

작성일: 2026-08-23  
저장소: `youtube` (패키지명 `finalent`)  
프레임워크: Next.js 14.2 App Router · React 18 · TypeScript  
로컬 개발: `npm run dev` → `http://localhost:3001`

이 문서는 **현재 코드 기준** 아키텍처·불변조건·주요 경로를 정리한 개발 백서다. 운영 소개는 `docs/서비스_소개서.md`, 구버전 개요는 `docs/시스템_소개서.md`를 참고하되, 저장소·인증·오버레이 규칙은 **이 백서를 우선**한다.

---

## 1. 한 줄 정의

방송 중 **계좌·투네이션 후원**을 실시간으로 멤버에 반영하고, OBS/Prism **오버레이**로 보여 주며, 방송 후 **정산서**를 계산·보관하는 웹 시스템이다.

## 4. 상태 저장 (Source of truth)

우선순위:

1. `UPSTASH_REDIS_REST_URL` + `UPSTASH_REDIS_REST_TOKEN` → Redis
2. `DATABASE_URL=mysql://…` → `app_kv` (`k`, `v` LONGTEXT, `expires_at`, `updated_at`)
3. 프로세스 메모리

핵심 타입은 `AppState` (`src/lib/state.ts`): `members`, `donors`, `missions`, `overlayPresets`, `donorRankingsTheme`, 타이머·시그·상류사회 설정, `updatedAt`, `settlementResetAt` 등.

**후원이 바뀌는 순간**(합산·붙여넣기·투네 ingest·삭제·복구) 서버 KV에 **즉시 저장**한다. 테마만 저장한다고 후원 목록을 비우면 안 된다.

### 4.1 멀티탭 병합

- 비교 키: `updatedAt`, 후원 목록 union
- 의도적 축소(단건 삭제)는 허용, **우발적 전체 비우기**는 `zero-wipe-guard` 등으로 거부
- 관리자 일반 저장은 서버 후원을 통째로 덮어쓰지 않는다 (`omitDonationFields` / `donorsAuthoritative` 정책)

## 5. 인증과 쓰기 API (IDOR)

| 구분 | 동작 |
|------|------|
| 읽기 GET / OBS | `?u=` 우선, 없으면 쿠키. 로컬은 `finalent` 우회 |
| 관리자성 쓰기 | **로그인 쿠키 필수**. `?u=`만으로 쓰기 거부 |
| 쿠키와 `?u=` 둘 다 | 값이 다르면 403 `user_mismatch` |
| OBS·투네 릴레이·룰렛 | `resolveWriteUserId(..., { allowAnonymousUrlUser: true })` |

구현: `src/app/api/_shared/user-id.ts`  
로컬 호스트는 `isDevAuthBypassRequest`로 쓰기 우회가 된다.

KV `SET` 실패 시 룰렛/후원 저장은 `{ ok: false }` / HTTP 503 `persist_failed`로 전파한다 (`saveAppStateForRoulette`).

정산·daily-log·queue 등 서버 스토어를 쓰는 라우트는 **Edge가 아니라 `nodejs` runtime**이다.

## 6. 후원 파이프라인

### 6.1 공통 적용

수동 합산·일괄·투네 자동반영은 같은 경로를 탄다.

```
이벤트 → applyDonationToAppState → donors union → saveAppStateForRoulette → SSE
```

- 진입: `/api/donations/apply` (수동), ingest (투네)
- 상태 변환: `src/lib/donation/apply-donation-state.ts`
- 멤버 합계는 후원 목록에서 재계산 (`syncMemberTotalsFromDonors`)
- 표시·정산 금액은 **100원 단위 버림** 후 합산

### 6.2 투네이션 실시간 수집 — **프리즈** (2026-08-03)

사용자 명시 없이는 아래를 바꾸지 않는다.

1. **1순위**: EC2 Node WS (`server-listener.ts`) → `ws.toon.at` 단독 연결  
2. **fallback**: 서버 WS가 끊겼을 때만 브라우저 릴레이 (`ToonationBrowserRelay`, `deferToServerListener=true`)  
3. ingest: `ingestToonationWebSocketMessage` → `tryAutoApplyToonationDonationOnServer`

불변조건 요약:

- 서버 WS가 살아 있으면 오버레이/관리자 브라우저가 **같은 연동키로 별도 WS를 열지 않음**
- pause/OFF여도 Redis의 연동키·alertbox URL은 유지
- 통합알림창과 Alertbox가 같은 WS를 잡으면 수집 0건 → UI 경고 유지
- RAW WS dedupe 500ms, `externalId` 건별 unique, 실 id만 EVENT dedupe

상세: `.cursor/rules/toonation-auto-collect-freeze.mdc`

### 6.3 정산 리셋 (2026-08-06)

- 후원 **전체 초기화**와 `settlementResetAt` 상승은 관리자 **「정산 리셋」** (`settlementReset: true`)만 허용
- 투네 반영·테마 저장·폴링이 후원을 통째로 비우면 안 됨
- 단건 삭제는 허용

### 6.4 기타 후원 기능

- 단체짠 나누기: `src/lib/donation/group-split-donation.ts`
- 미매칭 후원: `/api/donations/unmatched`, `resolve`
- 별칭: `/api/donations/aliases`
- 큐: `/api/donations/queue`
- 로컬 더미: `POST /api/dev/seed-donations` `{ preview: "split10" }` (localhost only)

## 7. 정산

페이지/API에 계산식을 **인라인하지 않는다.** 반드시 `computeSettlement()`.

대략:

- 멤버별 계좌·투네 원금 → 100원 버림
- 계좌비율·투네비율·수수료(기본 3.3%)
- 선택: 부가세 포함 스냅샷 → 공급가 환산 (`toSettlementBaseAmount`)
- 운영비 행·국고 행은 이름/직급/플래그로 판별 (`isOperatingSettlementMember`, `isTreasurySettlementMember`)
- 운영비는 순위·기여도 표시에서 제외되고 표 하단에 고정되는 경우가 많음

기록 API: `/api/settlements`, 복구 `recover`, 로고·문구, 삭제 로그. Daily Log는 운영 데이터 API 추가 시 연계 여부를 PR에 명시한다.

## 8. 오버레이 (OBS)

기본 URL: `/overlay?u={userId}&p={presetId}&host=obs`

| 경로 | 역할 |
|------|------|
| `/overlay` | 엑셀 멤버표, 목표바, 티커, 타이머, 미션 |
| `/overlay/donor-rankings` | 후원자 순위 (계좌+투네 통합, `all=1` 전원) |
| `/overlay/high-society` | 상류사회 영토 바 |
| `/overlay/sig-sales` | 시그 회전판 |
| `/overlay/sig-match` | 시그 대전 |
| `/overlay/meal-match` | 식사 대전 |
| `/overlay/obs-text` | 다중 텍스트 인스턴스 |
| `/overlay/goal` | 목표 막대만 |
| `/overlay/dev` | 로컬 점검 허브 (production 404) |

동기화: GET `/api/state?u=` + SSE. OBS는 쿠키가 없으므로 **읽기는 `?u=`** 가 정석이다.

### 8.1 5인 이상 좌우 스플릿

공통: `splitOverlayListAtHalf()` (`src/lib/utils.ts`)

- 4명 이하: 1열
- **5명 이상**: 앞쪽 절반(올림) 왼쪽, 나머지 오른쪽 (5→3+2, 10→5+5)
- 엑셀표: `/overlay` 멤버 행. 총합·운영비 핀은 오른쪽 표
- 후원순위: 통합 목록에 동일 규칙. 오른쪽 순위는 `rankOffset`으로 이어짐
- `layout=dual`은 **계좌열 / 투네열** 분리이지, 인원 반 나눔이 아님

### 8.2 엑셀표 테마

`src/lib/excel-member-table-theme.ts`

- 수동 HEX가 있으면 테마 자동색을 가림 → 관리자 「표 색 전부 테마 자동」으로 클리어
- 헤더/패널/총합 테두리는 테마 id로 해석 (`resolveTableThemeHeaderBgCss` 등)
- Studio Glass: `globals.css` / Tailwind (`backdrop-blur`, 반투명 패널)

### 8.3 순위 규칙

엑셀표 `buildOverlayRankedMembers`:

- 직급 **대표**는 맨 위, 순위 표시 없음
- 나머지: 후원 총액 내림차순, 동점이면 **멤버 생성순**
- 운영비는 호출측에서 하단 핀

후원순위: 후원자 이름 집계 (`donor-rankings-aggregate`). 서버 `donorRankingsWire`가 있으면 cap된 donors 대신 wire를 쓴다.

## 13. 변경 시 체크리스트

1. 정산식을 페이지에 새로 쓰지 않았는가 → `computeSettlement()`만
2. 후원 전체 리셋/`settlementResetAt`을 테마·폴링이 올리지 않는가
3. 투네 ingest·릴레이·parse를 **요청 없이** 건드리지 않았는가
4. 쓰기 API가 쿠키 없이 `?u=`만으로 동작하지 않는가 (OBS 예외는 명시)
5. 운영성 API면 Daily Log 반영 여부를 적었는가
6. 오버레이 스플릿·순위 정렬·100원 버림을 깨지 않았는가
