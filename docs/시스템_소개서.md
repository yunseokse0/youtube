# DIN Studio (youtube) 시스템 소개서

작성일: 2026-10-16  
저장소: `youtube` (패키지명 `finalent`)  
운영 앱: Next.js 14 App Router · React 18 · TypeScript  
로컬: `npm run dev` → `http://localhost:3001`  
라이브: `http://3.37.127.90` (EC2 + Nginx + pm2)

비개발 소개는 `docs/서비스_소개서.md`, 구현 불변조건은 `docs/개발백서.md`를 우선한다.

---

## 1. 한 줄 정의

방송 중 **계좌·투네이션·DIN 허브 후원**을 실시간으로 멤버에 반영하고, OBS/Prism **오버레이**로 보여 주며, 방송 후 **정산서**를 계산·보관하는 웹 시스템이다. 같은 상태 위에 **시그 판매**, **상류사회 영토**, **식사·시그 대전** 등 방송 연출이 붙는다.

|------|------|---------|

| OBS/Prism | `/overlay?...&host=obs` | 엑셀표, 순위, 시그 휠, 상류사회, 알림 |
| 정산 담당 | `/settlements` | 비율 적용, TXT/CSV/PDF, 과거 기록 |

계정은 `?u=`로 분리된다. 예: `u=din`, `u=finalent`, `u=paeza`.

## 3. 시스템 구성

```
[투네이션 Alertbox / DIN Hub]
        │  WS 또는 POST ingest
        ▼
[youtube Next.js :3000]  ← Nginx :80
        │
        ├─ KV: Upstash Redis 우선, 없으면 MySQL app_kv, 둘 다 없으면 메모리
        ├─ SSE /api/events  +  오버레이 폴링 GET /api/state?u=
        └─ OBS 브라우저 소스 (쿠키 없음 → 읽기는 ?u=)
```

| 분류 | 기술 |
|------|------|
| 앱 | Next.js 14.2, Node 20–22 |
| UI | React 18, Tailwind, framer-motion |
| 저장 | Redis → MySQL `app_kv` → 메모리 |
| 후원 수집 | 투네 서버 WS, DIN hub ingest Bearer |
| 정산 | `computeSettlement()` 만 사용 |
| 배포 | EC2, Nginx, pm2 (`deploy/deploy-on-ec2.sh`) |
| 모바일 | Capacitor 8 Android 웹뷰 |

라이브 오버레이 서버 공인 IP는 **3.37.127.90**. DIN 허브는 **13.125.221.195:4000**.

## 4. 핵심 기능

### 4.1 후원

- 수동 합산·붙여넣기, 단체짠 나누기, 미매칭 해결, 별칭
- 투네이션: EC2 Node가 `ws.toon.at`에 단독 연결. 서버 WS가 살아 있으면 브라우저가 같은 키로 또 열지 않음
- DIN 허브: 스트림 키로 계정 연결. 한 PC에서 연결하면 같은 로그인 계정의 다른 PC에서도 세션이 유지된다. 후원은 서버에서 계속 쌓인다
- 표시·정산 금액은 **100원 단위 버림** 후 합산
- 후원 전체 비우기와 `settlementResetAt`은 관리자 **정산 리셋**만 허용. 테마 저장·폴링이 후원을 지우면 안 됨

### 4.2 오버레이 (OBS)

기본: `/overlay?u={userId}&p={presetId}&host=obs`

| 경로 | 역할 |
|------|------|
| `/overlay` | 엑셀 멤버표, 총합, 목표바, 티커, 타이머, 미션 |
| `/overlay/donor-rankings` | 후원자 순위 |
| `/overlay/high-society` | 상류사회 영토 바 |
| `/overlay/sig-sales` | 시그 회전판·당첨 카드 |
| `/overlay/sig-match`, `/overlay/meal-match` | 대전 |
| `/overlay/obs-text` | 다중 텍스트 |
| `/overlay/goal` | 목표 막대만 |
| `/player-alert` | 시그 GIF·플레이어 알림 |
| `/admin.html` · `/overlay.html` | 상류사회 전용 백오피스·보드 (public 정적) |

5명 이상이면 표를 좌우로 나눈다. OBS 첫 페인트에서 URL을 읽기 전에 빈 화면을 그리지 않는다 (`host=obs` 하이드레이션).

### 4.3 시그 판매

- 관리자에서 등록·이미지 업로드·한방 시그·판매 완료 스탬프
- DIN에서 시그 가져오기(`POST /api/toona/signatures`)는 허브 목록을 받은 뒤 저장. 로그인 응답을 막지 않도록 가져오기는 뒤로 미룬다
- 휠은 가격 있는 판매 시그만. 한방 시그는 별도 연출
- 수동 판매 오버레이는 이름·금액이 OBS에서 읽히도록 카드 비율·푸터 대비를 맞춘다

### 4.4 상류사회

- 멤버별 cm 영토, 부여·지정·뺏기·벽 진입·균등
- 영토 기록(`grantLog`)은 `/api/shangliu`에 계정별로 저장
- **시스템 초기화**는 영토 기록을 비우고 서버에 바로 저장한다. 정산 리셋은 영토를 지우지 않는다
- 양쪽 **벽은 회색**. 멤버 영토 색과 구분한다

### 4.5 정산

- 식은 페이지에 쓰지 않고 `src/lib/settlement-utils.ts` → `computeSettlement()`
- 계좌비율·투네비율·수수료(기본 3.3%), 운영비·국고 행 구분
- 기록은 `/api/settlements`, TXT/CSV/PDF, 최대 보관 정책은 정산 모듈 기준

## 5. 인증과 데이터 권한

| 구분 | 동작 |
|------|------|
| 읽기 GET / OBS | `?u=` 우선, 없으면 쿠키 |
| 관리자 쓰기 | 로그인 쿠키 필수. `?u=`만으로 쓰기 거부 |
| 쿠키와 `?u=`가 다름 | 403 `user_mismatch` |
| DIN ingest | `Authorization: Bearer` (ingest 시크릿). 본문에 시크릿을 적지 않는다 |

저장 우선순위: Redis → MySQL `app_kv` → 메모리(재시작 유실).

핵심 상태 `AppState`: 멤버, 후원, 미션, 오버레이 프리셋, 시그, 상류사회 설정, `updatedAt`, `settlementResetAt`.

후원이 바뀌는 순간 서버 KV에 즉시 저장한다. 멀티탭은 후원 목록을 병합하고, 우발적 전체 비우기는 거부한다.

## 7. DIN 허브 연동 (시나리오 B)

운영 중인 youtube는 DIN이 시트를 건너뛰고 ingest로 **집계+시그**를 넘기는 B모드다.

```
POST /api/donations/ingest?u={userId}
Authorization: Bearer {ingestSecret}
```

스트림 키로 허브에 연결하면 세션이 계정(`userId`) 기준으로 남는다. 엑셀 집계는 ingest가 권위다.

## 8. 배포

```bash
cd ~/youtube
git pull --ff-only
bash deploy/deploy-on-ec2.sh
```

- `pm2 delete youtube`를 배포 앞에 붙이지 않는다. 프로세스가 없으면 스크립트가 기동한다
- `public/admin.html`, `public/overlay.html`은 정적 파일이라 pull 후 기동만으로도 반영된다
- 전체 Next 빌드는 수 분이 걸린다. 중간에 `^C`하면 서비스가 빈다
- MySQL 3306은 외부에 열지 않는다
